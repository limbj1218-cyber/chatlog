# 오토워커 봇 (Arisa2 판)

메신저봇R에서 돌던 **오토봇**(자동응답·대화기록)과 **카페봇**(네이버 카페 새글 알림)을
[Arisa2](https://github.com/ye-seola/arisa2) 위로 옮긴 것이다. 기능은 1:1로 같다.

## 왜 옮겼나

| | 메신저봇R | Arisa2 |
|---|---|---|
| 코드가 도는 곳 | 폰 위의 Rhino 엔진 | **아무 PC** (단말기는 창구만) |
| 먼저 말 걸기 | `BotManager.getCurrentBot().send()` 하나만 겨우 | `reply(channel_id, …)` 정식 API |
| 네트워크 대기 | 메시지 흐름을 막으면 **앱 전체가 멈춤** (2026-09-07 사고) | asyncio — 서로 간섭 없음 |
| 코드 배포 | 로더가 깃헙 raw 에서 본체를 받아 `eval` | `git pull` |
| 문법 | ES5만 (let/const/화살표 금지) | 파이썬 3.11+ |

두 봇을 스크립트로 **나눠야 했던 이유**(하나가 멈추면 다른 하나까지 죽음)가 사라져서
한 프로세스 안의 두 모듈로 합쳤다.

## 구조

```
 [패드/폰]                          [항상 켜 두는 PC]
 ┌───────────────┐   gRPC :3000   ┌──────────────────────────┐
 │ arisa 바이너리 │ ◄────────────  │  python -m autoworker    │
 │  (창구 역할만) │                │   ├ 자동응답 + 대화기록    │
 └───────────────┘                │   └ 카페 새글 감시        │
        ▲                         └──────────┬───────────────┘
        │ 카톡 DB 폴링                        │ git pull / raw
   [카카오톡]                            [깃헙 chatlog]
```

자동응답 내용은 메신저봇R 판과 **같은 파일**(`bot/오토봇데이터.json`)을 쓴다.
옮기는 동안 양쪽이 어긋나지 않는다.

## 준비

### 1. 패드에 arisa 올리기

[릴리스](https://github.com/ye-seola/arisa2/releases)에서 `arisa-arm64-v8a` 를 받아 실행한다.
**밖에서 붙을 수 있게 바인드 주소를 확인할 것** — 기본값이 이미 `0.0.0.0:3000` 이라
보통 그대로 두면 된다.

```sh
ARISA_BIND=0.0.0.0:3000 ./arisa
```

- 패드와 PC가 **같은 네트워크(같은 공유기)** 에 있어야 한다.
- 패드의 내부 IP를 알아둔다 (설정 → Wi-Fi → 연결된 네트워크). 예: `192.168.0.10`

### 2. PC 준비

```bash
git clone https://github.com/limbj1218-cyber/chatlog.git
cd chatlog/bot/arisa
cp .env.example .env
```

`.env` 를 열어 두 줄을 채운다.

```ini
ARISA_TARGET=192.168.0.10:3000   # ← 패드 IP
GITHUB_TOKEN=ghp_...             # ← 카페 알림용 (없으면 카페 기능만 꺼짐)
```

> **`.env` 는 절대 깃헙에 올리지 않는다.** `.gitignore` 에 들어 있다.
> 토큰에 필요한 권한은 `cafe-watch` Contents 읽기 + `chatlog` Actions 쓰기 두 가지다.

[uv](https://docs.astral.sh/uv/getting-started/installation/) 를 설치한다. 그게 전부다.

### 3. 실행

- **윈도우**: `run.bat` 을 더블클릭
- **리눅스·맥**: `./run.sh`

이 스크립트가 하는 일은 셋이다 — 깃헙에서 최신 코드 받기(`git pull`) → 의존성 맞추기
(`uv sync`) → 봇 실행. 봇이 죽으면 10초 뒤에 다시 띄운다.

uv 없이 쓰려면:

```bash
python -m venv .venv && .venv/bin/pip install -e .
.venv/bin/python -m autoworker
```

## 첫 실행에서 할 일

봇은 방을 **이름**으로 알고 있지만 Arisa2 는 숫자 `channel_id` 로 다룬다.
메시지가 올 때마다 짝을 배워 `rooms.json` 에 남기므로, 한 번 배우면 껐다 켜도 기억한다.

다만 **처음 켠 직후에는 아직 아무 방도 모른다.** 카페 새글 알림처럼 먼저 말 거는
기능은 그 방에서 메시지가 한 번 올라온 뒤부터 동작한다. 기다리기 싫으면
각 방에서 `/방정보` 를 한 번씩 쳐주면 바로 배운다.

```
/방정보
→ 🏷️ 방 정보
  이름: [오토2]
  channel_id: 12345678901234
  ...
```

방 이름이 설정과 다르게 나오면(공백·특수문자 등) `src/autoworker/config.py` 의
`ROOMS` 를 그 이름에 맞춘다.

## 명령어

| 명령 | 누가 | 어디서 | 하는 일 |
|---|---|---|---|
| `/오토` | 누구나 | 모든 방 | 진단 (연결·데이터·트리거 수) |
| `/방정보` | 누구나 | 모든 방 | 방 이름과 channel_id |
| `/리스트` | 누구나 | 등록된 방 | 이 방의 자동응답 목록 |
| `/오토업데이트` | 관리자 | 등록된 방 | 자동응답 내용 즉시 갱신 |
| `/삭제내역` `/삭제내역1` `/삭제내역2` | 누구나 | 공백기 근무표 | 기록 조회 (이 방 / 오토2 / 오토2프프) |
| `/카페` | 누구나 | 등록된 방 | 카페 감시 상태 |
| `/카페확인` | 관리자 | 등록된 방 | 지금 바로 카페 확인 |
| `/발송테스트` | 관리자 | 등록된 방 | 알림 방에 실제로 보내보기 |

관리자는 대화명에 `후파`·`임병진`·`[오차율 계산봇]` 이 들어간 사람이다.

## 갱신

| 바뀐 것 | 반영 방법 |
|---|---|
| 자동응답 내용 (`bot/오토봇데이터.json`) | 깃헙에 push → 30분 안에 자동, 급하면 `/오토업데이트` |
| 봇 코드 (이 폴더) | 깃헙에 push → PC에서 봇 창을 닫았다 `run.bat` 다시 실행 |

## 설정

`src/autoworker/config.py` 한 파일에 모여 있다. 방 목록, 관리자, 쿨다운(20분),
기록 보관 수(3000), 카페 확인 주기(3분) 등.

## 자동응답 규칙

메신저봇R 판과 같다.

1. **전체 일치**가 언제나 우선이고 쿨다운이 없다.
2. 트리거 이름이 `*` 로 시작하면 그 낱말이 **들어 있기만 해도** 응답한다.
3. 포함 매칭의 쿨다운은 트리거 이름이 아니라 **내보낼 내용**으로 묶는다.
   `*질문` 과 `*궁금` 처럼 같은 안내를 가리키는 낱말이 여럿이어도 한 방에 20분에 한 번.

## 시험

단말기 없이 로직만 돌려볼 수 있다.

```bash
python tests/test_logic.py
```

## 아직 옮기지 않은 것

이번은 1:1 이식이라 **지금 되는 것만** 그대로 옮겼다. Arisa2 라서 가능해지지만
아직 손대지 않은 것들:

- **삭제 감지** — `FeedMessageDeleted` 이벤트가 지워진 원문까지 준다.
  지금 `/삭제내역` 은 여전히 "시각으로 대조" 방식이다.
- **카톡 DB 직접 조회** — `RawQuery` 가 있어 대화를 따로 3000개씩 쌓지 않아도 된다.
- **네이버 카페 직접 호출** — 봇이 PC 에서 도니 깃헙 Actions 경유가 필요 없어질 수 있다.
  다만 검증 전까지는 확인된 경로를 그대로 쓴다.
