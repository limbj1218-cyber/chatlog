# 루나·토마토·레몬·사건봇 StarLight(NeonJS) 설치 가이드

메신저봇R 판(`bot/루나봇.js`·`bot/토마토봇.js`·`bot/레몬봇.js`·`bot/사건봇.js` 와 각 로더)은 **그대로 남아 있다.**
옮기다 안 되면 메신저봇R 쪽 봇을 다시 켜면 된다.

| 봇 | 붙여넣을 로더 | 방 | 로더 명령 | 데이터 파일 |
|---|---|---|---|---|
| 루나봇 | `bot/starlight/루나봇로더.js` | 루나 | `/루나업데이트` `/루나로더` `/루나가져오기` | `luna_Database.json` |
| 토마토봇 | `bot/starlight/토마토봇로더.js` | 토마토 | `/토마토업데이트` `/토마토로더` `/토마토가져오기` | `tomato_Database.json` |
| 레몬봇 | `bot/starlight/레몬봇로더.js` | 레몬 | `/레몬업데이트` `/레몬로더` `/레몬가져오기` | `lemon_Database.json` |
| 하늘봇 | `bot/starlight/하늘봇로더.js` | 하늘 | `/하늘업데이트` `/하늘로더` `/하늘가져오기` | `sky_Database.json` |
| 사건봇 | `bot/starlight/사건봇로더.js` | 사건 | `/사건업데이트` `/사건로더` `/사건가져오기` | `Database.json` |

`/내정보` 는 다섯 봇 모두 같다. 업데이트·가져오기는 대화명에 "후파"가 들어간 사람만
(사건봇은 그 밖에 사업처임병진·가이아✡·가이어트 — 정확히 같은 대화명. 사건봇엔 알림 기능이 없다).
사건봇 데이터 파일은 메신저봇R 때부터 `Database.json` 이다 — 메신저봇R 폴더의 그 파일을 Download 에 넣고 `/사건가져오기`.
클로드 토큰 파일(`claude_token.txt`)은 메신저봇R 때와 달리 **프로젝트마다 따로**다 — 봇마다 가져오거나 `/클로드토큰` 으로 넣는다.

## 1. StarLight 설치

- **GitHub 판 APK**를 받는다: https://github.com/mooner1022/StarLight/releases (2026-11-14 기준 v1.2.0)
  - Play 스토어 판은 일부 자바 기능을 막아 두고, 데이터가 앱을 지우면 같이 지워진다 → GitHub 판 권장
- 처음 켜면 묻는 권한을 모두 허용한다: **알림 접근**, **다른 앱 위에 표시**, **모든 파일 접근**
- 설정 → 일반 → **배터리 최적화 예외**도 켜 둔다 (안 켜면 화면이 꺼졌을 때 알림이 늦거나 멈춘다)

## 2. 메신저봇R 의 같은 봇 끄기

두 앱이 같이 켜져 있으면 그 방에서 둘 다 답한다. 메신저봇R 에서 **옮기는 봇만 끈다** (지우지 말 것 — 되돌릴 때 쓴다).

## 3. 프로젝트 만들기 (봇마다 하나)

StarLight → 프로젝트 → **새 프로젝트**

| 항목 | 값 |
|---|---|
| 이름 | 아무거나 (예: `루나봇스타`) — 로더는 이름이 아니라 "지금 이 프로젝트" 폴더를 쓴다 |
| 언어 | **NeonJS** |
| API 방식 | **StarLight 원본** + **메신저봇 API2** (둘 다 체크) |
| 받을 이벤트 | `starlight.message.create` (onMessage) |

만든 뒤 **수정**을 눌러 StarLight 가 넣어 둔 기본 코드를 **전부 지우고** 그 봇의 로더를 통째로 붙여넣는다
(기본 코드를 남기면 `onMessage` 가 두 번 선언돼 컴파일이 실패한다). → **컴파일** → 켜기.

- 컴파일할 때 로더가 깃헙에서 **로더 코어**(`bot/starlight/○○봇로더코어.js`)와 본체(`bot/starlight/○○봇.js`)를 받아
  프로젝트 폴더에 `○○_core.js`·`○○_body.js` 로 둔다. 인터넷이 되는 상태에서 컴파일할 것. 한 번 받으면 그 뒤로는 깃헙이 안 돼도 돈다.
- **붙여넣는 로더는 "틀"이라 거의 바뀌지 않는다** (2026-11-17 부터). 로더 기능이 바뀌어도 방에서 `/○○업데이트` 만 치면
  본체와 로더 코어를 함께 새로 받는다. 다시 붙여넣는 건 틀 자체가 바뀔 때뿐이다(드물다).
  `/○○로더` 첫 줄에 `로더 core-… · 틀 틀-…` 이 보이면 틀이 깔린 것이다. `틀 옛 로더` 로 나오면 예전 로더라 한 번 다시 붙여넣을 것.

## 4. 데이터 옮기기 (재련 기록·등록 명령어·클로드 토큰)

메신저봇R 판은 데이터 파일과 `claude_token.txt` 를 메신저봇 앱 폴더에 두었다
(보통 `내장 메모리/Android/data/com.xfl.msgbot/files/`).

1. 파일 관리자로 그 봇의 데이터 파일과 `claude_token.txt` 를 **`내장 메모리/Download/`** 에 복사한다
   (안드로이드 11 이상은 Android/data 가 안 보일 수 있다 — 그러면 PC 에 연결해서 복사)
2. 그 방에서 관리자가 `/○○가져오기` → 두 파일을 StarLight 프로젝트의 data 폴더로 가져오고 다시 불러온다
   - 다른 곳에 두었으면 `/○○가져오기 /sdcard/폴더경로`
   - 이미 있던 StarLight 쪽 파일은 `.bak` 으로 남긴다
3. `/랭킹` 으로 기록이 이어졌는지 본다

> 데이터를 안 옮겨도 봇은 돈다. 루나·토마토는 본체에 들어 있는 11/14 랭킹 손질(`luna-ranking-2026-11-14`·`tomato-ranking-2026-11-14`)이
> 랭킹 이름 3명이 말한 뒤 저절로 들어간다. 레몬은 손질이 없어 1부터 시작한다. 등록 명령어·클로드 토큰은 새로 넣어야 한다.

## 5. 확인할 것

| 방에서 | 볼 것 |
|---|---|
| `/○○로더` | 본체 버전 ✅, 데이터 폴더, 알림 시계 `setInterval` |
| `재련가즈아` (본인) | **내 이름으로** 옛 단계에서 이어지는지 |
| `/알림 (2분 뒤) 테스트` → `0` → `오늘만` | 그 시각에 "⏰ 테스트" 가 오는지 |
| `..` → `.안녕` | 1~2분 뒤 클로드 답이 오는지 (토큰을 넣었을 때) |

카톡 없이 시험하려면 프로젝트의 **디버그** 방을 쓴다. 디버그 방 설정에서 **방 이름을 그 봇의 방 이름**(루나·토마토·레몬)으로
바꿔야 봇이 반응한다.

> **사람 구분은 대화명으로 한다** (2026-11-16). StarLight 가 주는 사람 구분 값(`sender.id`)은 알림에 쌓인 **첫 메시지**에서
> 읽어 와서, 앞사람 것이 섞여 온다 — 후파의 재련이 바로 앞에 말한 엑시아 기록으로 처리된 적이 있다.
> 그래서 StarLight 판은 그 값을 쓰지 않는다. 대화명을 바꾸면 새 사람으로 잡힌다(카톡 DB 감지를 켜면 대화명 변경은 따로 알 수 있다).

## 5-1. 입퇴장·닉변·삭제 감지 (네 봇 모두, 카톡 DB 플러그인)

카톡 알림에는 입장·퇴장·삭제가 오지 않는다. **카톡 DB 플러그인**(KakaoDB, github.com/mooner1022/starlight-kakaodb)이
카톡 데이터베이스를 읽어 이 이벤트들을 준다. 카톡 DB 는 카톡만 읽을 수 있는 곳에 있어서 플러그인 설정의 **접근 방식**이
**루트**(루팅한 폰) 또는 **공유 UID**(플러그인 초기 설정에서 카톡을 패치해 다시 설치) 여야 한다.

1. StarLight 에 KakaoDB 플러그인을 넣고 초기 설정을 마친다 → 플러그인 설정 **연결 → 상태** 가 연결됨인지 본다
2. 플러그인 설정의 **onMessage 호환 이벤트** 는 **꺼 둔다** (켜면 메시지가 두 번 와서 재련이 두 번 된다)
3. 봇 프로젝트마다 → 받을 이벤트에 `kakaodb.member.join` · `kakaodb.member.leave` · `kakaodb.message.create` · `kakaodb.message.delete` 추가
4. **로더를 다시 붙여넣는다** (sl-1116-3 이상 — 카톡 DB 이벤트를 받는 함수가 로더에 생겼다) → 컴파일
5. 방에서 `/감지` → `카톡 DB: 연결됨 ✅`. `/○○로더` 에도 `카톡 DB 감지` 줄이 있다

| 일 | 봇이 하는 말 |
|---|---|
| 처음 온 사람 | `OO님 어서오세요` |
| 전에 있던 사람이 다시 옴 | `OO님 돌아오신걸 환영해요` |
| 대화명을 바꿔 다시 옴 | `OO님(구 XX님) 돌아오신걸 환영해요` |
| 나감 / 내보내짐 | `OO님이 나가셨어요` / `OO님이 내보내졌어요` |
| 말할 때 대화명이 바뀌어 있음 | `🔄 대화명 변경: XX → OO` |
| 메시지를 지움 | `🗑️ OO님이 메시지를 지웠어요` + 지운 내용 (사진 등은 종류만) |

- 사람은 **카톡 회원 ID** 로 구분한다 (정확하다). 기록은 data 폴더 `luna_kakao.json`(토마토 `tomato_kakao.json`, 레몬 `lemon_kakao.json`, 사건 `sageon_kakao.json`)
- 처음 쓰는 날 첫 이벤트 때 지금 방 멤버를 미리 적어 둔다 — 원래 있던 사람이 나갔다 오면 "돌아오신걸" 로 맞이한다
- 관리자가 `/감지 입장 끄기` (입장·퇴장·닉변·삭제·전부, 켜기·끄기). `/닉변감지` 는 이 기록으로 보여준다
- 플러그인이 없거나 끊겨 있으면 감지만 조용히 멈추고 나머지 기능은 그대로 돈다

## 6. 업데이트

본체를 고쳐 깃헙에 올리면 그 방에서 관리자가 `/○○업데이트`.
새 본체를 먼저 읽어 보고 문제없을 때만 바꾸며, 옛 본체는 `○○_body_prev.js` 로 남긴다.

## 7. 되돌리기

StarLight 의 그 프로젝트를 끄고 메신저봇R 의 그 봇을 다시 켠다.
StarLight 에서 쌓인 기록은 StarLight 프로젝트의 `data/○○_Database.json` 에 있으니, 필요하면 메신저봇R 폴더로 다시 복사한다.

# 오토봇 · 카페봇 (2026-11-16 추가)

게임봇 세 개(루나·토마토·레몬)와 만드는 방법은 같고, **방마다 만드는 게 아니라 봇마다 프로젝트 하나**다.

| | 오토봇 | 카페봇 |
|---|---|---|
| 메인 스크립트 | `bot/starlight/오토봇로더.js` | `bot/starlight/카페봇로더.js` |
| 본체 (자동으로 받음) | `bot/starlight/오토봇.js` | `bot/starlight/카페봇.js` |
| 프로젝트 안 본체 파일 | `auto_body.js` | `cafe_body.js` |
| data 폴더에 두는 것 | `오토봇캐시.json` `대화기록.json` `사람.json` `등록응답.json` `프반응답.json` `멱살응답.json` | `카페봇상태.json` `gh_token.txt` |
| 로더 명령 | `/오토업데이트` `/오토로더` `/오토가져오기` `/내정보` | `/카페업데이트` `/카페로더` `/카페가져오기` `/카페강제확인` |

**두 봇은 프로젝트를 따로 만든다.** 한 프로젝트에 같이 두면 카페 쪽 네트워크·시계가 자동응답까지 끌고 내려간다
(메신저봇R 에서 2026-09-07 에 겪어 나눠 둔 이유 그대로다).

## 오토봇

- 방 목록 기본값은 로더 코어(`오토봇로더코어.js`)의 `MY_ROOMS` 에 있다(틀의 `SETTINGS` 에 적으면 그게 먼저).
  본체의 `EXTRA_ROOMS`(`[오차율 계산봇]`·`공백기 근무표`·`멱살반2`)는 로더에 없어도 동작한다 — 메신저봇R 판과 같다.
- 자동응답 내용(`bot/오토봇데이터.json`)은 **깃헙에서 받아** data 폴더에 캐시한다. 깃헙이 안 되면 캐시로 버틴다.
- `/오토업데이트` 는 본체 버전이 같으면 **자동응답 내용만** 다시 받고 진단을 붙여 답한다(다시 컴파일하지 않는다).
  버전이 달라졌을 때만 본체를 바꾸고 다시 컴파일한다.
- StarLight 의 `event.sender.id` 는 **앞사람 것이 섞여 와서**(위 5번 참고) 로더 sl-1116-2 부터 쓰지 않는다.
- **입퇴장·닉변·삭제 감지** (2026-11-16): 게임봇과 같은 조각(`kakaodb_watch.js`)이 들어 있다 — 위 5-1 의 설정(카톡 DB 플러그인 연결,
  받을 이벤트 4개, 로더 다시 붙여넣기) 그대로. 알림은 **일어난 그 방에 바로** 보낸다(오토2·오토2프프·[오차율 계산봇]·공백기 근무표·멱살반2).
  `/감지` 는 누구나, `/감지 입장 끄기` 등은 대화명에 후파·임병진·[조교] 가 든 사람. 기록은 data 폴더 `auto_kakao.json`.
  `/닉변감지` 도 이 기록으로 보여준다. 로더를 붙여넣은 뒤 **`/오토업데이트`** 로 본체도 바꿔야 한다(본체 `1116-1s2` 이상).
- **오픈프로필 입장 안내** (오토봇만): 카카오톡 기본 프로필이 아닌 사람이 들어오면 기본 프로필로 바꿔 달라는 글과 안내 사진을 보낸다.
  - 사진은 폰의 `Download/오픈프로필안내.jpg` (다른 사진은 관리자가 `/프로필사진 /sdcard/폴더/파일.jpg`)
  - 사진은 카톡 공유 화면을 거쳐 가므로 StarLight 의 **다른 앱 위에 표시** 권한이 켜져 있어야 한다. 폰이 잠겨 있으면 안 갈 수 있다
  - `/내프로필` 로 내 프로필 종류 값을 본다 — 기본 프로필 계정이 `1` 이 아니면 알려 줄 것(값의 뜻이 공식 문서에 없다)
  - `/감지 프로필 끄기`·`켜기` (방마다), `/감지` 에 사진 경로와 마지막 보내기 결과가 보인다

## 카페봇

- **깃헙 토큰은 로더 파일에 적지 말 것** (`MY_TOKEN` 은 비워 둔다). 방에서 `/깃토큰 <토큰>` 으로 넣으면
  data 폴더의 `gh_token.txt` 에 저장된다. 단톡방에서 넣었으면 그 메시지를 지울 것.
  권한은 메신저봇R 판과 같다 — cafe-watch Contents 읽기 + chatlog Actions 쓰기.
- 새 글 알림은 봇이 **먼저 말을 걸어야** 하므로 로더가 `PLAT.send`(봇 send → `Chat.findRoom` → 마지막 방 객체)로 맡는다.
  `/카페강제확인` 으로 한 바퀴 돌려 실제로 가는지 보고, 안 가면 `/카페로더` 의 **발송 방식**을 볼 것.
- 메신저봇R 판은 앱 전체(JVM) 공유값으로 **스크립트가 중복 설치돼도** 같은 글이 두 번 안 나가게 막았는데,
  StarLight 는 프로젝트마다 따로 돌아 그런 값이 없다. **같은 카페를 보는 프로젝트를 둘 만들지 말 것.**
- 시계는 `setInterval` 하나다. 다시 컴파일하면 옛 시계가 저절로 꺼져 세대 장치가 필요 없다.
