# 루나·토마토·레몬봇 StarLight(NeonJS) 설치 가이드

메신저봇R 판(`bot/루나봇.js`·`bot/토마토봇.js`·`bot/레몬봇.js` 와 각 로더)은 **그대로 남아 있다.**
옮기다 안 되면 메신저봇R 쪽 봇을 다시 켜면 된다.

| 봇 | 붙여넣을 로더 | 방 | 로더 명령 | 데이터 파일 |
|---|---|---|---|---|
| 루나봇 | `bot/starlight/루나봇로더.js` | 루나 | `/루나업데이트` `/루나로더` `/루나가져오기` | `luna_Database.json` |
| 토마토봇 | `bot/starlight/토마토봇로더.js` | 토마토 | `/토마토업데이트` `/토마토로더` `/토마토가져오기` | `tomato_Database.json` |
| 레몬봇 | `bot/starlight/레몬봇로더.js` | 레몬 | `/레몬업데이트` `/레몬로더` `/레몬가져오기` | `lemon_Database.json` |

`/내정보` 는 세 봇 모두 같다. 업데이트·가져오기는 대화명에 "후파"가 들어간 사람만.
클로드 토큰 파일(`claude_token.txt`)은 메신저봇R 때와 달리 **프로젝트마다 따로**다 — 봇마다 가져오거나 `/클로드토큰` 으로 넣는다.

## 1. StarLight 설치

- **GitHub 판 APK**를 받는다: https://github.com/mooner1022/StarLight/releases (2026-11-14 기준 v1.2.0)
  - Play 스토어 판은 일부 자바 기능을 막아 두고, 데이터가 앱을 지우면 같이 지워진다 → GitHub 판 권장
- 처음 켜면 묻는 권한을 모두 허용한다: **알림 접근**, **다른 앱 위에 표시**, **모든 파일 접근**
- 설정 → 일반 → **배터리 최적화 예외**도 켜 둔다 (안 켜면 화면이 꺼졌을 때 알림이 늦거나 멈춘다)

## 2. 메신저봇R 의 같은 봇 끄기

두 앱이 같이 켜져 있으면 그 방에서 둘 다 답한다. 메신저봇R 에서 **옮기는 봇만 끈다** (지우지 말 것 — 되돌릴 때 쓴다).

## 3. 프로젝트 만들기 (봇마다 하나)

StarLight → 프로젝트 → **새 프로젝트**

| 항목 | 값 |
|---|---|
| 이름 | 아무거나 (예: `루나봇스타`) — 로더는 이름이 아니라 "지금 이 프로젝트" 폴더를 쓴다 |
| 언어 | **NeonJS** |
| API 방식 | **StarLight 원본** + **메신저봇 API2** (둘 다 체크) |
| 받을 이벤트 | `starlight.message.create` (onMessage) |

만든 뒤 **수정**을 눌러 StarLight 가 넣어 둔 기본 코드를 **전부 지우고** 그 봇의 로더를 통째로 붙여넣는다
(기본 코드를 남기면 `onMessage` 가 두 번 선언돼 컴파일이 실패한다). → **컴파일** → 켜기.

- 컴파일할 때 로더가 깃헙에서 본체(`bot/starlight/○○봇.js`)를 받아 프로젝트 폴더에 `○○_body.js` 로 둔다.
  인터넷이 되는 상태에서 컴파일할 것. 한 번 받으면 그 뒤로는 깃헙이 안 돼도 돈다.

## 4. 데이터 옮기기 (재련 기록·등록 명령어·클로드 토큰)

메신저봇R 판은 데이터 파일과 `claude_token.txt` 를 메신저봇 앱 폴더에 두었다
(보통 `내장 메모리/Android/data/com.xfl.msgbot/files/`).

1. 파일 관리자로 그 봇의 데이터 파일과 `claude_token.txt` 를 **`내장 메모리/Download/`** 에 복사한다
   (안드로이드 11 이상은 Android/data 가 안 보일 수 있다 — 그러면 PC 에 연결해서 복사)
2. 그 방에서 관리자가 `/○○가져오기` → 두 파일을 StarLight 프로젝트의 data 폴더로 가져오고 다시 불러온다
   - 다른 곳에 두었으면 `/○○가져오기 /sdcard/폴더경로`
   - 이미 있던 StarLight 쪽 파일은 `.bak` 으로 남긴다
3. `/랭킹` 으로 기록이 이어졌는지 본다

> 데이터를 안 옮겨도 봇은 돈다. 루나·토마토는 본체에 들어 있는 11/14 랭킹 손질(`luna-ranking-2026-11-14`·`tomato-ranking-2026-11-14`)이
> 랭킹 이름 3명이 말한 뒤 저절로 들어간다. 레몬은 손질이 없어 1부터 시작한다. 등록 명령어·클로드 토큰은 새로 넣어야 한다.

## 5. 확인할 것

| 방에서 | 볼 것 |
|---|---|
| `/○○로더` | 본체 버전 ✅, 데이터 폴더, 알림 시계 `setInterval` |
| `/내정보` | `보낸 사람 hash: 있음 ✅` — 없으면 사람 구분이 대화명 기준으로 돈다 |
| `재련가즈아` (본인) | **옛 단계에서 이어지는지** — 이어지면 StarLight 의 hash 가 메신저봇R 과 같은 값이다. 1부터 새로 시작하면 hash 가 다르다는 뜻이니 알려 줄 것 (이름으로 이어 붙이는 손질이 필요) |
| `/알림 (2분 뒤) 테스트` → `0` → `오늘만` | 그 시각에 "⏰ 테스트" 가 오는지 |
| `..` → `.안녕` | 1~2분 뒤 클로드 답이 오는지 (토큰을 넣었을 때) |

카톡 없이 시험하려면 프로젝트의 **디버그** 방을 쓴다. 디버그 방 설정에서 **방 이름을 그 봇의 방 이름**(루나·토마토·레몬)으로
바꿔야 봇이 반응한다 (디버그 방에서는 hash 가 없어 대화명 기준으로 기록된다).

## 6. 업데이트

본체를 고쳐 깃헙에 올리면 그 방에서 관리자가 `/○○업데이트`.
새 본체를 먼저 읽어 보고 문제없을 때만 바꾸며, 옛 본체는 `○○_body_prev.js` 로 남긴다.

## 7. 되돌리기

StarLight 의 그 프로젝트를 끄고 메신저봇R 의 그 봇을 다시 켠다.
StarLight 에서 쌓인 기록은 StarLight 프로젝트의 `data/○○_Database.json` 에 있으니, 필요하면 메신저봇R 폴더로 다시 복사한다.
